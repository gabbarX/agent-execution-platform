# Demo M1 — Walking Skeleton

Assumptions: repo root, Go 1.27+, PowerShell 7. Two terminals (server +
client), or run the server with `Start-Process`.

## 1. Run lifecycle

Terminal 1:

```powershell
go run ./cmd/controlplane -workers 2
```

Expected: `controlplane: listening on :8080 (workers=2, weights=map[])`

Terminal 2:

```powershell
$r = Invoke-RestMethod -Method Post -Uri http://localhost:8080/runs `
  -Body '{"team":"a","agent":"demo","version":1}' -ContentType 'application/json'
$r
Invoke-RestMethod -Uri "http://localhost:8080/runs/$($r.id)"   # repeat a few times
```

Expected: first response `status: QUEUED`; repeated GETs show `RUNNING`
with `steps_done` climbing 1→8 (~300 ms per step), then `SUCCEEDED`
with `steps_done: 8` and `finished_at` set.

## 2. Idempotent create

```powershell
$a = Invoke-RestMethod -Method Post -Uri http://localhost:8080/runs `
  -Body '{"team":"a","agent":"demo","version":1,"idempotency_key":"pay-42"}' -ContentType 'application/json'
$b = Invoke-RestMethod -Method Post -Uri http://localhost:8080/runs `
  -Body '{"team":"a","agent":"demo","version":1,"idempotency_key":"pay-42"}' -ContentType 'application/json'
"$($a.id) == $($b.id)"
```

Expected: both IDs identical — the retry did not start a second run.

## 3. Cancel a running run

```powershell
$c = Invoke-RestMethod -Method Post -Uri http://localhost:8080/runs `
  -Body '{"team":"a","agent":"demo","version":1}' -ContentType 'application/json'
Start-Sleep -Milliseconds 800
Invoke-RestMethod -Method Post -Uri "http://localhost:8080/runs/$($c.id)/cancel"
Start-Sleep -Milliseconds 300
Invoke-RestMethod -Uri "http://localhost:8080/runs/$($c.id)"
```

Expected: cancel returns the run (202, often still RUNNING); the
follow-up GET shows `CANCELLED` with `steps_done < 8`. Cancelling again
returns 409 `run already CANCELLED`.

## 4. Fairness — a burst cannot starve another team

Restart the server with **one** worker so ordering is visible:

```powershell
go run ./cmd/controlplane -workers 1 -weights "bulk=1,interactive=1"
```

Terminal 2 — 12 bulk runs, then 2 interactive runs:

```powershell
1..12 | ForEach-Object { Invoke-RestMethod -Method Post -Uri http://localhost:8080/runs `
  -Body '{"team":"bulk","agent":"demo","version":1}' -ContentType 'application/json' | Out-Null }
1..2 | ForEach-Object { Invoke-RestMethod -Method Post -Uri http://localhost:8080/runs `
  -Body '{"team":"interactive","agent":"demo","version":1}' -ContentType 'application/json' | Out-Null }
Start-Sleep -Seconds 13   # ~5 runs complete at 2.4s each
(Invoke-RestMethod -Uri "http://localhost:8080/runs?team=interactive").runs | Select-Object id, status
(Invoke-RestMethod -Uri "http://localhost:8080/runs?team=bulk").runs | Where-Object status -eq "SUCCEEDED" | Measure-Object | Select-Object Count
```

Expected: **both** interactive runs SUCCEEDED while most of the bulk
backlog is still QUEUED (~3 bulk done). With a global FIFO the
interactive runs would have waited ~29 s behind all 12 bulk runs;
weighted fair queuing served them 2nd and 4th.
